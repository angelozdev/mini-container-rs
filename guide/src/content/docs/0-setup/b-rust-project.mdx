**Al terminar:** el repo tiene un proyecto de Rust llamado `mini-container` que compila y corre en Linux, y Zed analiza tu código como código de Linux.

El código se escribe en el Mac, con Zed, dentro de la carpeta del repo: `/Users/tu-usuario/mini-container-rs`. Se compila y se corre en Linux. La máquina de <Term id="orbstack">OrbStack</Term> ve esa misma carpeta, en la misma ruta, así que los dos lados trabajan sobre los mismos archivos. Falta un detalle: Zed usa un programa llamado <Term id="rust-analyzer">rust-analyzer</Term>, que lee tu código mientras escribes y marca los errores. Por defecto lo lee con las reglas de macOS.

## Los pasos

<Steps>

1. **Crea el proyecto.** En Linux, en la raíz del repo:

   ```sh title="En Linux"
   cargo init --name mini-container
   ```

   - `cargo`: la herramienta de Rust que compila, corre y administra proyectos.
   - `init`: crea un proyecto de Rust en la carpeta actual, la raíz del repo. `new` haría lo mismo pero en una carpeta nueva.
   - `--name mini-container`: el nombre del <Term id="crate">crate</Term>. Un crate es un paquete de Rust: aquí, tu programa. Sin esta opción, `cargo` usaría el nombre de la carpeta, `mini-container-rs`. En Rust el sufijo `-rs` suele marcar el lenguaje del repo y no va en el nombre del crate.
   - Efecto: crea `Cargo.toml` y `src/main.rs` en la raíz del repo, y deja un `Cargo.lock` cuando compilas por primera vez.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ cargo init --name mini-container
       Creating binary (application) package
   note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
   ```

   </ShouldSee>

   «Binary (application)» significa que el crate es un programa y no una librería.

   Esto es lo que crea. `Cargo.toml` es la ficha del proyecto: su nombre, su versión y sus dependencias.

   ```toml title="Cargo.toml"
   [package]
   name = "mini-container"
   version = "0.1.0"
   edition = "2024"

   [dependencies]
   ```

   Y `src/main.rs` es un programa de ejemplo. En 1a lo reemplazarás:

   ```rust title="src/main.rs"
   fn main() {
       println!("Hello, world!");
   }
   ```

   `cargo init` también tocó tu `.gitignore`. Le añadió dos líneas al final: el comentario `# Added by cargo` y `/target`. `/target` es la carpeta donde `cargo` deja lo que compila, y no debe ir a git. Ya estaba cubierta por `target/`, así que git ignora lo mismo que antes. Pero el archivo cambió, y `git status` lo muestra como modificado. Puedes dejar ese cambio y guardarlo en un commit.

2. **Córrelo en Linux.**

   <Quiz kind="prediction">
   <Fragment slot="question">Corres `cargo run` por primera vez en este proyecto. ¿Qué hace?</Fragment>

   <QuizOption>Solo compila. Para ver el resultado hay que correr el binario aparte.<Fragment slot="feedback">Eso es `cargo build`. `cargo run` compila y además corre el programa.</Fragment></QuizOption>

   <QuizOption correct>Compila el proyecto y corre el programa.<Fragment slot="feedback">Si el código ya estaba compilado y no cambió, se salta la compilación y solo lo corre.</Fragment></QuizOption>

   <QuizOption>Solo corre. Antes hay que compilar con `cargo build`.<Fragment slot="feedback">No hace falta. `cargo run` compila lo que falte antes de correr.</Fragment></QuizOption>
   </Quiz>

   ```sh title="En Linux"
   cargo run
   ```

   - `run`: compila el proyecto y corre el binario resultante.
   - Efecto: crea la carpeta `target/` con lo compilado y el archivo `Cargo.lock`, que fija las versiones exactas de las dependencias.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ cargo run
      Compiling mini-container v0.1.0 (/Users/tu-usuario/mini-container-rs)
       Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
        Running `target/debug/mini-container`
   Hello, world!
   ```

   </ShouldSee>

   - `Compiling`: está compilando tu crate.
   - `Finished ... in 0.08s`: terminó. El tiempo cambia en cada máquina. `dev` es el perfil por defecto: compila rápido, sin optimizar, y deja información para depurar.
   - `Running`: ejecuta el binario que quedó en `target/debug/mini-container`.
   - `Hello, world!`: la salida del programa.

   El binario es un archivo normal. Puedes correrlo sin `cargo`:

   ```sh title="En Linux"
   ./target/debug/mini-container
   ```

   - `./target/debug/mini-container`: la ruta del binario. El `.` es la carpeta actual. Como la ruta lleva `/`, el <Term id="shell">shell</Term> la usa tal cual y no la busca en el `PATH`.
   - Efecto: corre el programa, sin `cargo` de por medio.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ ./target/debug/mini-container
   Hello, world!
   ```

   </ShouldSee>

3. **Instala el target de Linux en el Mac.** Un <Term id="target">target</Term> es la plataforma para la que se compila. Su nombre, la <Term id="target-triple">tripleta</Term>, tiene partes:

   - `aarch64`: la arquitectura del procesador, la misma de tu Mac.
   - `unknown`: el fabricante. Aquí no importa.
   - `linux`: el sistema operativo.
   - `gnu`: la librería de C que usa, la de GNU.

   En el Mac, en cualquier carpeta:

   ```sh title="En el Mac"
   rustup target add aarch64-unknown-linux-gnu
   ```

   - `rustup`: el instalador y actualizador de Rust. Ya lo tienes en el Mac.
   - `target add`: instala un target.
   - `aarch64-unknown-linux-gnu`: la tripleta de Linux sobre tu procesador.
   - Efecto: descarga la librería estándar de Rust compilada para ese target y la añade a tu instalación de Rust en el Mac. Sirve para que Zed entienda el código de Linux. No sirve para compilar programas de Linux desde el Mac: para eso faltaría un enlazador, y compilamos en Linux.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ rustup target add aarch64-unknown-linux-gnu
   info: downloading component rust-std
   ```

   </ShouldSee>

   Pueden salir más líneas que empiecen con `info:`, o una barra de progreso. Si ya tenías el target, `rustup` no descarga nada y dice `info: component rust-std for target aarch64-unknown-linux-gnu is up to date`: *up to date* significa «ya está al día».

   Comprueba que quedó instalado:

   ```sh title="En el Mac"
   rustup target list --installed
   ```

   - `target list`: lista los targets que `rustup` conoce.
   - `--installed`: deja solo los que tienes instalados.
   - Efecto: solo imprime.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ rustup target list --installed
   aarch64-apple-darwin
   aarch64-unknown-linux-gnu
   ```

   </ShouldSee>

   `aarch64-apple-darwin` es el target de tu Mac, y ya estaba.

4. **Dile a Zed qué plataforma revisar.** Zed lee un archivo de ajustes por proyecto, `.zed/settings.json`. Crea la carpeta en el Mac, en la raíz del repo:

   ```sh title="En el Mac"
   mkdir .zed
   ```

   - `mkdir`: crea una carpeta.
   - `.zed`: el nombre que Zed espera. El punto inicial la hace oculta.

   Dentro, crea `settings.json` con este contenido:

   ```json title=".zed/settings.json"
   {
     "lsp": {
       "rust-analyzer": {
         "initialization_options": {
           "cargo": {
             "target": "aarch64-unknown-linux-gnu",
             "targetDir": true
           }
         }
       }
     }
   }
   ```

   - `lsp`: los ajustes de los <Term id="language-server">language servers</Term>. Un language server es un programa que lee tu código y le dice al editor qué marcar. rust-analyzer es el de Rust.
   - `rust-analyzer`: el servidor al que se refieren los ajustes de abajo.
   - `initialization_options`: las opciones que Zed le entrega a rust-analyzer al arrancarlo.
   - `cargo`: el grupo de opciones sobre cómo rust-analyzer llama a `cargo`.
   - `target`: la plataforma para la que revisa. Es la tripleta del paso anterior.
   - `targetDir`: con `true`, rust-analyzer revisa en una subcarpeta propia dentro de `target/`, y no en la que usa `cargo build`. El Mac y Linux comparten la carpeta del repo, y por tanto `target/`. Así lo que revisa el editor en el Mac no choca con lo que compilas en Linux. El precio es que duplica algunos archivos compilados.

   Zed reinicia el servidor solo cuando guardas cambios en la sección `lsp.rust-analyzer`.

   Para ver la diferencia, añade esta línea al principio de `src/main.rs`, en el Mac. Esa ruta solo existe en Linux:

   ```rust title="src/main.rs"
   use std::os::linux::fs::MetadataExt;
   ```

   Sin el ajuste, rust-analyzer revisa para macOS y la marca como error. Con el ajuste revisa para Linux y solo avisa de que no se usa. Puedes ver los mismos dos resultados con `cargo check` en la <Term id="terminal">terminal</Term> del Mac. Primero, revisando para macOS:

   ```sh title="En el Mac"
   cargo check
   ```

   - `cargo check`: revisa el código como si fuera a compilarlo, pero sin generar el binario. Es lo que rust-analyzer corre por dentro.

   <ShouldSee>

   ```sh title="Deberías ver" stderr={2-6}
   $ cargo check
   error[E0433]: failed to resolve: could not find `linux` in `os`
    --> src/main.rs:1:14
     |
   1 | use std::os::linux::fs::MetadataExt;
     |              ^^^^^ could not find `linux` in `os`
   ```

   </ShouldSee>

   La salida real es más larga. Estas son sus primeras líneas, sin la línea `Checking`. Y ahora para Linux, que es lo que rust-analyzer hace con tu ajuste:

   ```sh title="En el Mac"
   cargo check --target aarch64-unknown-linux-gnu
   ```

   - `--target aarch64-unknown-linux-gnu`: revisa para esa plataforma.

   <ShouldSee>

   ```sh title="Deberías ver"
   $ cargo check --target aarch64-unknown-linux-gnu
   warning: unused import: `std::os::linux::fs::MetadataExt`
    --> src/main.rs:1:5
   ```

   </ShouldSee>

   Ya no hay error. Solo queda el aviso de que el `use` no se usa. Aquí también está recortada la salida. Borra esa línea de `src/main.rs` antes de seguir.

</Steps>

<Aside type="caution" title="Trampa típica">
Si no pones el target en Zed, todo el código que usa funciones de Linux, que será casi todo el programa desde la parte 2, saldrá marcado en rojo aunque compile bien en Linux. El error está en la configuración del editor, no en tu código. Como regla: la verdad la dice `cargo build` en Linux, no el subrayado de Zed.
</Aside>

### 0b.1 Averigua la tripleta de tu máquina Linux

**Objetivo:** en `.zed/settings.json` escribiste la tripleta de Linux. Ahora averigua, preguntándoselo a `rustc` dentro de Linux, cuál es la tripleta de esa máquina. Confirma que es la misma que escribiste.

```sh title="Resultado esperado"
$ rustc -vV | grep host
host: aarch64-unknown-linux-gnu
```

<Hint n={1}>`rustc --version` imprime una sola línea. Mira en `rustc --help` cómo pedir más detalle.</Hint>

<Hint n={2}>La opción corta de `--version` es `-V`. Con `-v`, de *verbose*, añade más líneas. Se pueden juntar: `-vV`.</Hint>

<Hint n={3}>La salida trae varias líneas. `grep host` deja solo la que tiene la palabra `host`. Pásale la salida de `rustc` con `|`.</Hint>

## Fuentes

- Zed, «Rust», sección «Alternate Targets»: la clave `lsp.rust-analyzer.initialization_options.cargo.target` hace que rust-analyzer dé diagnósticos para otra plataforma. Y: el servidor se reinicia solo cuando se guarda la sección `lsp.rust-analyzer`. [zed.dev/docs/languages/rust](https://zed.dev/docs/languages/rust). Consultada el 2026-11-12.
- Zed, «Configuring Zed», «Project Settings»: `.zed/settings.json` en la raíz del proyecto sustituye los ajustes de usuario para ese proyecto. [zed.dev/docs/configuring-zed](https://zed.dev/docs/configuring-zed). Consultada el 2026-11-12.
- rust-analyzer, `cargo.target`: «Compilation target override (target tuple)». [rust-analyzer.github.io/book/configuration.html](https://rust-analyzer.github.io/book/configuration.html). Consultada el 2026-11-12.
- rust-analyzer, `cargo.targetDir`: «Optional path to a rust-analyzer specific target directory. This prevents rust-analyzer's `cargo check` and initial build-script and proc-macro building from locking the `Cargo.lock` at the expense of duplicating build artifacts. Set to `true` to use a subdirectory of the existing target directory or set to a path relative to the workspace to use that path.». Misma página. Consultada el 2026-11-12.
- `rustup target add` y `rustup target list --installed`: salidas de rustup 1.29.0 en el Mac, el 2026-11-12.
- `.gitignore` tras `cargo init`: salida real de cargo 1.99.1 sobre un repo de git con un `.gitignore` previo. Cargo añadió una línea en blanco, `# Added by cargo`, otra línea en blanco y `/target`. El 2026-11-12.
- `rustc -vV`: imprime la versión con detalle, incluida la línea `host`. Comprobado en la máquina Linux (`host: aarch64-unknown-linux-gnu`) el 2026-11-12.
- Salidas de `cargo` en Linux: máquina Ubuntu 26.04.1 `aarch64`, Rust 1.99.1. Salidas en el Mac: Rust 1.94.0. Ambas el 2026-11-12.
